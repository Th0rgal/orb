## Refactoring proposal: fewer independent contracts, observable effects

This was the audit-phase ordered proposal; implementation is now authorized under the ledger above, with operator-only deployment and dev verification before merge. Estimates are **engineer-days including focused tests/review**, not measured delivery commitments. Each implementation PR must be one bounded vertical slice or foundation; the numbered sections below are workstreams, **not a claim that an entire cross-platform workstream fits one PR**. Split broad families into explicit follow-ups rather than replacing the server wholesale. Security gates ship before convenience features. Do not run optimization experiments against a moving or weakened behavioral specification.

**Prerequisite for every slice, not a final-stage task:** freeze independently reviewed expectations and a real-entrypoint regression gate before changing that family. Preserve safe Rust compatibility; where historical behavior is insecure or deliberately retired, use an explicitly reviewed replacement expectation rather than unconditional equality to Rust output. Expand the general harness in §7 later, but never postpone the applicable observable oracle until after a migration.

**Sensitive-capability release gate:** a restored capability cannot become supported until its applicable authority/signature, spend/resource bound, cancellation, redaction and required audit-write controls pass negative integration tests. §6 centralizes those policies incrementally; it does **not** defer their enforcement. Return unsupported/uncertain instead of exposing an effect while its safety prerequisites remain absent.

Use **plain idiomatic Lean declarations** over domain types; no external spec-combinator dependency and no mandatory new wrapper hierarchy. Reuse an existing local contract abstraction only where it genuinely fits. Each changed top-level contract needs a short Human Spec Card pinned to repo/commit/files: intent and harm, requirement→declaration map, one reachable positive trace, proved claims, meaningful bug-mutant rejection, unchecked extractor/JSON/POSIX/FFI assumptions, and outside-scope behavior. Pure queries preserve state. Local transactional mutations frame untouched projections and roll back **before their local commit**; an already committed external effect cannot be assumed rolled back because a later receipt/audit write failed. Model its uncertain outcome and reconciliation explicitly. Genuinely shared budgets/permissions require conservation laws, not fictitious disjoint owners. Clause independence, disjoint outcome cases, and disjoint storage are different obligations. No mechanical audit proves completeness against unmodeled requirements.

Keep implementation candidates unable to edit their own frozen judge. A proposed internal relaxation requires a semantic-preservation theorem for the original externally admitted inputs, a transitive definition/dependency-closure review (not only theorem-type hashes), retained two-sided meaningful mutant regressions, and independent review. Changing the external promise, admitted input domain, tolerance, or trust boundary is a Thomas decision, not a proof repair. Preserve legitimate `rfl` proofs rather than adding ceremony to satisfy heuristics.

### 0. One authenticated subject and verified admission facts (2–3 days foundation; targeted containment PRs first)

**Refactor:** give authentication, session ownership, signed approval, placement trust and lease issuance one typed authority boundary. HTTP, MCP and node adapters receive an `AuthenticatedPrincipal` resolved to a live owner/session, never a Boolean password verdict or an invented admin. Preserve legacy identity through an explicit migration; absence/invalidity cannot map to another principal. Device-approved operations receive evidence from a real signature/challenge verifier bound to exact method/path/body, device, subject and expiry. A helper cannot set a `biometricSigned` or `hasProjectSkill` fact merely because a request exists or a project string is nonempty. Obtain placement, actual skill attachment, lineage and secret access from their authoritative stores. Node signing must require the resolved role/Unix identity and never silently default a missing identity to admin.

Keep these concrete domain types small and owned, not a new framework. Public request/response DTOs are not verified authority: do not derive client-supplied JSON decoders for private approval/principal/completion-evidence constructors. Derive authorization once at the common boundary, then enforce object-specific owner/lineage guards in the domain owner as well. A device signature is not equivalent to a bearer token; a user scope is not a mission-tree scope; project equality is not a grant; TTL is not session liveness.

**Specs under `lean/Orb`:** state preservation of the authenticated subject, scoped authority of issued capabilities, challenge single-use/body binding, and revocation/session-lifetime constraints in plain propositions over decoded principals and authority records. Connect the repository's existing policy gates to honest extractor premises: if raw JWT/JSON/P-256 verification remains in the I/O/crypto TCB, the Spec Card must say so. A theorem over supplied booleans cannot certify those booleans were extracted faithfully. Do not assume a compressing hash is globally injective to prove request identity; state the actual crypto trust assumption or a bounded per-trace collision premise explicitly.

**CI closure:** exercise the actual admission adapters with wrong user/mission/session, disabled/demoted/unknown subjects, revoked sessions and grants, absent/replayed/expired/wrong-body signatures, managed versus trusted placement, ordinary project versus attached skill, and missing node identity. A valid token for one scope must not accidentally mint another. Run those before restoring any currently stubbed sensitive effect.

### 1. Contract owner for routes and MCP tools (2–3 days first vertical slice; 2–4 additional days for reusable cross-platform integration; 1–2 days per subsequent family)

**First vertical slice:** use one existing read-only owner and one contract family, initially Resources overview: independently freeze its public DTO and authorized projection, then exercise the real handler and the actual TS/Swift/Kotlin decoders on success/error/empty/partial fixtures. The first 2–3 days covers that bounded slice, not generation for every route. Extract reusable machinery only where this slice demonstrably deletes duplicate definitions. The additional 2–4 days covers reusable generation/platform-test integration; re-estimate from the slice before broad migration.

**Refactor:** introduce a small typed route/capability declaration used by the `OrbCore.Control` dispatcher, the `OrbCore.R7Core` request boundary, and `OrbCore.McpGateway`, with method/path, request decoder, response encoder, error/status contract, required principal scope, capability support, and effective limits. Keep effectful implementations in their existing domain modules. Do not make one giant handler or maintain a second hand-written schema table. Share domain decoders between HTTP and MCP where the semantics are actually the same; keep the two transport envelopes explicit.

Generate TypeScript types/validators, Swift `Codable` models, Kotlin serialization models, and fixtures from the same wire contract. Preserve explicit JSON `null` versus absent, list versus object, snake_case field names, ISO timestamps, pagination/cursor order, and error codes. Validate the generated artifacts in CI and run the **actual client decoders**, not three copies of a server-side assertion, against the same success/error/empty/partial fixtures. A failed/partial decode must preserve last-good state outside the response's owned projection; only an explicit removal event deletes data. Begin with Resources, mission/event reads, settings/credentials, and fleet summaries. Existing projection fixtures in `shared/orb-spec/fixtures` are useful but are not a complete HTTP schema registry. Reuse the existing OrbWire envelope and client codec boundary (`lean/OrbClient/OrbClient/Reducers.lean:26–39,85–89`, `lean/OrbClient/OrbClient/Spec.lean:312–328`) rather than adding a competing binary protocol; its schema/payload round-trip does not establish the JSON payload's endpoint-specific meaning.

**Specs under `lean/Orb`:** add a wire-domain model and codec laws (`decode (encode x) = some x`, required-field and invalid-input rejection, bounded pages and monotone cursor advancement). Define the expected public document independently of the handler's JSON construction. Existing `Orb.Spec.ProjectionStability` and `CostBound` can be reused. Do not prove only that encoding a hard-coded success literal returns that same literal.

**CI closure:** every registered historical contract maps to an implemented capability or an explicitly reviewed removal; every route/tool has valid, invalid, and authorization-negative fixtures; client parsers consume emitted bytes. A handler-name match does not satisfy the gate. Unmapped/unsupported contracts fail the capability audit rather than silently disappearing.

### 2. Explicit capability support and effect receipts (2–3 days foundation; 1–2 days per effect family)

**Refactor:** replace ad-hoc success JSON with a domain result such as `Unsupported | Rejected reason | Accepted operationId | Completed evidence | Failed error | Uncertain operationId`. A successful mutation must carry evidence from its effect owner; an asynchronous enqueue is acceptance, not completion. Keep completion-evidence constructors private to that owner and make the transport success encoder consume its result, so a route branch cannot manufacture completion from a JSON literal. The I/O adapter remains an explicit trusted/tested boundary, not something a pure theorem certifies by name. HTTP unsupported operations return an explicit not-implemented error (normally 501); MCP exposes a clear error, not a successful empty result. Keep idempotency keys and the original operation identity through transport uncertainty. Do not retry an uncertain effect as a fresh operation.

Use one effect interpreter/receipt adapter per domain (jobs, provider lifecycle, secrets, approvals, deployment); do not let a tool branch invent completion. Catch errors at the boundary and retain typed causes, with sanitized logs and caller-safe messages. Failed persistence must not return durable success; failure to write a required security audit must follow an explicit fail-closed policy rather than `catch _ => pure ()`.

**Specs:** extend the existing `EffectSafety`, `EffectLiveness`, `ReplayIdempotence`, and `MetaStepSpec` in `lean/Orb/Spec.lean:137–254`; retain the generation/cancellation fences in `lean/Orb/LifecycleSpec.lean:11–20` and remote uncertainty/acknowledgment model in `lean/Orb/ManagedNodeSpec.lean:12–27`. Define `Completed` to require matching operation/generation evidence. Each external-effect Spec Card must name its commit point, pre-effect authorization/audit prerequisites, durable operation identity, and post-effect uncertainty/reconciliation rule; a later local write failure cannot imply the external effect never happened. Prove the positive path requires the expected effect and the negative/unsupported path cannot claim completion. **A pure proof of an emitted effect does not prove that I/O executed:** integration tests must verify the adapter and persisted receipt.

**CI closure:** inject unavailable provider, unwritable store, interrupted response, duplicate request, and restart; specifically test **external effect succeeded → receipt write failed → retry/restart**, preserving its original operation identity and reconciliation instead of declaring rollback or blindly re-executing. Assert no fabricated success, no double execution, and truthful durable/uncertain states. A real queued job test must observe a process and exit result; a `status:"completed"` string alone cannot pass.

### 3. Persisted documents have one owner and versioned codecs (2–3 days foundation; 1–2 days per store family)

**Refactor:** put each persisted settings/document/table codec behind its current state owner (`Store`, domain settings, credential broker, mission ledger). Handlers call owner APIs instead of assembling independent JSON paths or assuming API field names equal disk field names. Add explicit schema versions, dual-read/single-write migrations where needed, atomic replace/transactions, and preservation of fields not owned by a partial update. Treat malformed/unreadable existing state as an error or quarantine event, not an empty default that overwrites it. Keep encryption names/AAD and credential identifiers part of the migration contract.

**Specs:** model ownership and migration preservation: decode old state, migrate once, retain unrelated fields, preserve authorization semantics, write/read fixed point, idempotent migration. Prove these against a separately stated historic schema. Keep secret contents out of fixtures; use redacted synthetic values retaining real names, shapes, nullability, and versions.

**CI closure:** representative sanitized **actual pre-cutover files and database schemas**, plus zero/empty/missing/corrupt/unknown-field fixtures; read with Lean, perform one owner-authorized update, restart and read again. Check original tables, foreign keys, indexes, and migrations, not only fresh in-memory databases. No copy of a Rust binary is needed in the shipping tree; frozen Rust-output fixtures serve as independent expectations.

### 4. Register background duties, with heartbeat and restart semantics (2–3 days foundation; 1–2 days per duty family)

**Refactor:** replace scattered detached loops with a small registry in Core startup: stable duty ID, owner, startup reconciliation, cadence, prerequisite capability, last start/success/failure, deadline, bounded retry/backoff, shutdown and restart policy. Existing domain implementations remain owners; the registry schedules and reports, not duplicates their logic. A defined `reap` function without startup registration fails coverage. **Specs:** reuse `ClockDiscipline`, lifecycle boot/generation fences, and effect liveness. State the observable obligation for each duty (expired lease released, due continuation delivered once, ledger closed, stale sample marked stale) independently of the timer implementation. Separate elapsed/monotonic time from persisted wall-clock deadlines and preserve the intent across restart. A heartbeat means liveness, not progress or successful reconciliation.

**CI closure:** fake-clock integration tests boot the **real startup registry**, advance past deadlines, inject a failed tick, restart, and inspect state/effects. **Specs:** extend startup posture requirements around `OrbCore.Spec`'s startup gate (`lean/OrbCore/OrbCore/Spec.lean:61–112`), and place reusable environment/capability invariants under `lean/Orb`. ### 6. One policy for limits, costs, deadlines and redaction (2–3 days foundation; 1–2 days per proxy/execution family)

**Refactor:** define effective bounds once (request/body/page/log sizes; per-operation and idle/semantic deadlines; concurrency; CPU/RAM/disk; user/mission/provider spend reservations). Validate relationships at startup and admission, return the applied value and rejection reason, and propagate cancellation. Typed errors must distinguish unsupported, denied, invalid, provider failure, local persistence failure, timeout, cancellation, and uncertain delivery. Sanitize at one logging/response boundary, preserving correlation IDs and internal causes but not prompts, credentials or unredacted provider payloads. **Specs:** reuse `ConservedResource`, `CostBound`, `ClockDiscipline`, `ScopedAuthority`, commitment fences and the existing cost/deadline kernel. **CI closure:** boundary values at `limit−1`, `limit`, `limit+1`; streamed versus buffered responses; idle-but-alive and slow-first-byte providers; disconnect before/after commitment; simultaneous reservations; permission downgrade; forged scope; canary secret redaction; audit-write failure. Before optimizing, preserve this compatibility baseline, measure the actual bottleneck, constrain the experiment to a fixed spec and resource budget, compare to an unchanged baseline, and retain only reproducible improvements. **Cost/order summary:** first secure admissions and truthful results; then shared codecs/persistence; then required background registration and environment contracts; finally broader provider replay and simplification.
