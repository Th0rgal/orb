# Codex subscription speed in Orb

Speed is independent of reasoning effort. The new-agent composer, conversation footer and Codex fork menu expose Standard, Fast and Ultrafast through Orb's shared picker. A conversation's setting applies to its next turn; the running turn keeps its captured selection. Unavailable options explain why they cannot be selected. Saving an unavailable accelerated selection is rejected before execution admission.

`service_tier` is the canonical optional mission setting (`standard`, `fast`, `ultrafast`). Existing `fast_mode` records retain their meaning when no explicit tier exists. The wire identifiers are `default`, `priority`, and `ultrafast`. Mission storage, local-origin journals, forks, import/export and queued local dispatch preserve the selection. The legacy boolean is normalized when an explicit setting changes.

Eligibility comes from the account's live Codex usage report and account-specific model catalog, cached for one minute. An ambiguous `pro` claim does not establish Pro Max access. Ultrafast currently requires an eligible plan and an advertised Ultrafast tier for the selected model. Accelerated selections use subscriptions; they never grant a paid API fallback or a downgrade to another speed/model.

The Mac queries its installed Codex app-server's account/model catalog and verifies the selection before creating a native thread. Managed Core and node execution use the compatible subscription pool. When CLIProxyAPI owns OAuth, management API calls inspect capabilities without copying or refreshing OAuth credentials. CLIProxyAPI 8.0.26 or later is required for accelerated routing; older versions can discard the Ultrafast wire tier and are rejected during preflight. Dedicated account prefixes route inference to compatible accounts; original bare model routes remain registered. Shared prefixes and configurations that would remove existing bare routes are rejected. Reserved generated prefixes are hidden from Orb's model discovery.

Core-native Codex uses a revocable per-turn inference capability. The model remains its original Codex identifier, preserving its native model metadata and context window. The relay selects only compatible account routes and rotates on authentication, quota or server failures before a stream starts. The stable credential-owner identity and native thread remain unchanged. Node requests enforce their declared speed before any subscription request is sent. Custom-provider Codex may omit the wire tier even when its app-server accepted it: the authenticated execution selection or revocable capability supplies the tier at the transport boundary. An explicitly conflicting wire tier is rejected.

Direct native OAuth conversations remain bound to their original account; an incompatible account change requires an explicit fork. Proxy-backed conversations retain their logical proxy identity while compatible upstream accounts can rotate with full conversation-input replay. Stateful `previous_response_id` is refused on stateless subscription transports.

References: [OpenAI speed documentation](https://learn.chatgpt.com/docs/agent-configuration/speed), CLIProxyAPI account-prefix routing and management auth-file fields. Runtime read-only checks on 2026-10-12 confirmed Pro Max and the `priority`/`ultrafast` catalog identifiers on this Mac and the production proxy's healthy Codex account; the other tested production account returned HTTP 401 and was excluded.
