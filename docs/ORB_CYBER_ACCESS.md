# Orb cyber access

New Orb Codex drafts start in **Standard**. The picker follows the model selector.
**Daybreak** requests the selected model's approved cyber program; it neither
changes the model nor grants account authorization. **Automatic** omits an
explicit program and lets OpenAI select from that account's approved access.
Existing missions and older API clients retain Automatic until explicitly changed.
This setting does not change filesystem sandboxing, tool permissions, or pricing.
No equal-credit-cost guarantee is made.

The setting is saved per mission through `GET/PATCH /api/control/missions/:id/cyber`.
Changing it requires an idle mission and applies on its next launch, without
resuming it. Forks, clones, successors, local synchronization, and remote
continuations retain it. A new draft resets to Standard.

## Transport and authorization

Native ChatGPT-authenticated Codex connections check the selected account's
`model/list.availableAccessPrograms.cyber` and send `turn/start.cyberAccessProgram`.
Missing capability metadata is unsupported, not proof of an access denial.
An advertised list excluding the requested program is an access denial.
Native autonomous `/goal` continuations require an explicit Automatic selection:
the current protocol does not guarantee a per-turn choice on autonomous turns.
Native API-key connections likewise require Automatic or a supported connection.

Remote node Codex runs use the existing authenticated mission proxy. The driver
sets a program header, and Core maps it into official Responses `access_programs.cyber`.
Explicit selection requires a direct OpenAI route preserving the requested model;
unsupported intermediaries are rejected. The execution-issued proxy key pins both model and saved program. A missing header
cannot drop an explicit selection; conflicting headers or body fields fail closed.
Local follow-ups validate the fetched selection revision atomically with their
client-run permit, so another window cannot silently change a pending launch.
A provider 403 is returned unchanged,
without rotating accounts. Conflicting program fields are rejected.
The flag cannot bypass account approval or provider policy.

For GPT-6.1 Sol and GPT-6 Astra, Daybreak requests `daybreak_blue`; eligibility is
still determined by OpenAI and may require Red-level approval. Consult the current
[OpenAI Daybreak documentation](https://developers.openai.com/api/docs/guides/daybreak).

## Honest status and storage

Saving a preference means **requested**, never active. Remote confirmation requires
structured provider response metadata, tied to the current selection revision,
model, and execution-issued proxy key. Text generated by the assistant is not
confirmation. Native turn acceptance alone does not confirm activation.

Back up `mission-cyber/` under the configured Core working directory along with
mission data. It holds selection, execution-binding and provider-receipt sidecars;
no credentials. Corrupt selection files fail closed. Missing legacy selection
files retain Automatic. Generic mission export/import does not currently transfer
these sidecars: restore them as part of a full Core backup, or select the program
again after import.

## Rollout and verification

Deploy Core before using the updated Orb client. New clients check Core capability
version 2; local runs also require native IPC capability version 2. Older version 1 implementations cannot validate the atomic client selection and are rejected before launch. Old clients
continue their existing Automatic behavior. Remote drivers are embedded in Core,
so this change requires no account credentials or key distribution to leaf nodes.

Validation covers persistence, corrupt storage, stale execution keys and receipts,
SSE chunk preservation, native denial before turn start, remote command propagation,
and browser selection/save-error behavior. An operational acceptance test must
use a benign no-tools prompt and inspect both the mission result and cyber status.
A successful save or a model claiming Daybreak is active is not sufficient evidence.
