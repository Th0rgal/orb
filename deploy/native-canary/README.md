# Isolated native subscription canary

These standalone Linux units qualify a member workspace on a static HTTPS node before promoting native Antigravity. The existing node service, node token, worker storage and privilege socket have separate identities. The TLS configuration targets an nginx installation with the HTTP SSL and proxy modules.

## Prepare

1. Use a separate authenticated Core instance with only the permitted test member and its administrator. Set the member’s own Unix username and allow that member to use the test placement. Production and consent-bearing dev sessions retain their own store. Inspect the registered models on the canary and require successful inference on each requested model. An existing Core may issue appropriately scoped job credentials through its established proxy. Keep subscription secrets and provider keys on Core.
2. On the worker, ensure that the service user and group `orb-node` are available exclusively for this instance. The privilege broker accepts that named peer. Give the user a system UID, a nologin shell, and its own primary group. Verify that neither this user nor the node’s ordinary user can read the other node’s token, connect to its protected socket or enter its store. If the name already runs another service or its group is shared, use a different worker. Keep member Linux UIDs distinct from service accounts. The node executes member jobs with the signed lease’s member UID.
3. Stage the qualified node and privilege broker under `/opt/orb-native-tests/<commit>/bin/` and link `current` to that immutable revision. The units have no install target and must be started explicitly. Create a new root-owned `/etc/orb-native-tests` directory, mode 0755. Its redacted nginx configuration can be mode 0644. The separate `tls` directory and `node.env` must be root-only. The service manager reads the environment file before dropping privileges. Set `SANDBOXED_NODE_TOKEN` to a new scoped node credential and `ORB_CORE_API_URL` to the canary’s verified HTTPS origin. Provision the corresponding `SANDBOXED_REMOTE_NODE_NATIVE_TESTS_TOKEN` on that Core through its normal secret mechanism. Supply no other Core, cloud or provider keys to these services.
4. Render the two placeholders in `nginx.conf.in` with the literal private IPv4 addresses of the worker and the canary Core. Provision a TLS server certificate whose SAN covers the worker’s registered IP or DNS name. Place its public certificate chain and private key in `tls/worker.pem` and `tls/worker.key` respectively. Keep the private key on the worker. The new listener requires a mesh policy permitting precisely that Core to reach the worker on TCP 13443. Change the authoritative policy and verify denial from other peers before registration. Configure trust for this certificate on the canary. Keep ordinary TLS verification enabled.
5. Start the three units on the worker after package qualification. Register the separate static node on the canary only, with ID `native-tests` and verified `https://<worker>:13443` as the base URL. The ordinary worker retains its ID, port and services. Both the global and per-node dedicated-owner options are unsuitable for this shared-profile executor. Its admission checks the member, mission, node, run and short-lived grant. Only the canary’s enrolled test member may submit missions in this environment.
6. On the canary Core, provision the qualified private holder image, runtime and dedicated provider UID as documented in `docs/ANTIGRAVITY.md`. Provide bubblewrap and nsenter in its service PATH. Then enable the opt-in and set `ORB_NATIVE_WORKSPACE_NODE=native-tests`. Test TLS identity and rejection of invalid node credentials in both directions before the first mission. Record actual model, owner, parent, child, node, run and terminal inference for each harness in the Tests project. Check a different member’s denied file operation and the protected account’s exclusion from alternative routers.

## Roll back

Drain Tests, check the canary’s own active jobs, then revoke its grants. Disable its Core opt-in and remove its static roster entry. Stop the dedicated TLS, worker and privilege-broker units and revoke the separate node credential. Remove its mesh rule and scoped trust following their normal release procedures. Keep the canary evidence and job store until the operator’s retention deadline.

Run `sudo ./deploy/native-canary/check-tls.sh` on an isolated qualification host with nginx, Python 3, OpenSSL, curl and util-linux. It creates fresh namespaces with a loopback fixture and validates a trusted certificate, rejection of an untrusted certificate and denial from an unapproved source. Its processes and TLS material live only for the test. Check worker job-grant enforcement separately against the qualified binaries.
